# AI Research Copilot

전략 컨설턴트용 리서치 보조 도구. 리서치는 사람이 주도하고, 도구는 수집한 자료가 프로젝트 목표와 어떻게 맞는지 정리해 준다. 결론은 사람이 내린다.

컨설턴트가 리서치 목표를 문장으로 등록하면 서버가 이를 내부 가설 트리로 분해한다. 이후 자료를 붙여 넣을 때마다 그 자료가 어느 목표를 지지하는지, 반증하는지, 관련만 있는지, 무관한지를 원문 근거와 함께 판정한다.

## 구성

- 백엔드: FastAPI와 FastMCP가 한 프로세스에서 뜬다. MCP 엔드포인트는 `/mcp-server/mcp`, 웹앱용 REST는 `/api/*`이다.
- DB: PostgreSQL 16과 pgvector. 프로젝트(가설 트리), 분석한 자료와 판정 결과, 노드 임베딩(HNSW 인덱스), 일별 LLM 토큰 사용량을 저장한다.
- 모델: 판정은 Anthropic Claude(`claude-sonnet-5`), 후보 노드를 고르는 임베딩은 Voyage AI(`voyage-3`)를 쓴다.
- 프론트엔드: Next.js 14(`web/`). 목표 등록, 자료 입력, 판정 결과 화면이 있다.

## MCP 툴

- `set_project_brief(goal)`: 자연어 목표를 가설 트리로 분해해 저장한다. 목표가 너무 모호하면 명확화 질문 하나를 돌려준다.
- `analyze_content(project_id, content, source_url)`: 자료를 트리의 노드들과 대조해 노드별 판정을 반환하고 저장한다.
- `list_collected(project_id)`: 노드별로 지지·반증 자료 수, 필요한 근거 유형 중 채워진 것과 빈 것, 아직 어느 목표에도 기여하지 못한 자료를 보여준다.
- `find_synthesis_candidates(project_id)`: 빈 근거를 다른 자료로 채울 수 있는 연결을 제안한다. 연결 근거를 댈 수 없는 제안은 내보내지 않는다.
- `check_goal_drift(project_id)`: 리서치가 목표에서 벗어나고 있는지, 방치된 목표가 무엇인지 알려준다. 가설을 반증하는 자료도 목표에 기여한 것으로 센다.

## 판정 방식

1. 자료를 문장 단위 청크로 나누고, 임베딩 유사도로 후보 노드를 최대 5개 고른다. 유사도는 후보를 고르는 데만 쓴다.
2. 후보마다 Claude가 스탠스를 정한다. SUPPORTS, REFUTES, WEAK_RELATED(같은 문제 영역이지만 증거 부족), IRRELEVANT 네 가지다. 출력은 도구 호출로 형식을 강제하고 Pydantic으로 검증하며, 실패하면 한 번 재시도한다.
3. 근거 문장은 원문에 실제로 있는 문장만 남긴다. 지지나 반증이라고 했는데 남는 문장이 없으면 WEAK_RELATED로 낮춘다.
4. 근거 강도는 증거 유형 적합도, 출처 신뢰도, 최신성, 규모의 가중합이다. 자료에서 판단할 수 없는 요인은 0으로 채우지 않고 빼서 나머지로 다시 계산하며, 어떤 요인이 빠졌는지 함께 반환한다.

## 로컬 실행

`.env.example`을 `.env`로 복사하고 `ANTHROPIC_API_KEY`, `VOYAGE_API_KEY`를 채운다. `.env`는 git에 올라가지 않는다.

```bash
make up        # db, api, web 전체 기동
make ps        # 상태 확인
make down      # 정리 (데이터 볼륨은 남는다)
```

브라우저에서 `http://localhost:3000`으로 접속한다. 웹은 같은 출처의 `/api`를 부르고 웹 서버가 이를 api 컨테이너로 넘기므로, 원격 서버에서 띄웠다면 웹 포트 하나만 터널링하면 된다.

```bash
ssh -L 3000:localhost:3000 <user>@<server>
```

모든 포트는 `127.0.0.1`에만 열린다. 호스트에서 이미 쓰이는 포트가 있으면 `.env`에서 바꾼다: `WEB_PORT`(기본 3000), `API_PORT`(기본 8000, MCP 클라이언트와 curl용), DB는 5433 고정.

## 테스트와 평가

```bash
make test      # pytest, api 컨테이너 안에서 실행 (DB 필요)
make eval      # 골드셋 기준 판정 품질 평가
make label     # 골드셋 라벨링 CLI
```

평가는 SciFact 방식의 두 지표(스탠스만 보는 F1, 근거 문장까지 맞혀야 하는 F1)와 4x4 혼동행렬을 출력한다. 그 앞에 후보 재현율(정답이 지지/반증인 노드가 1단계 후보에 들었는지)과 근거 문장 탈락·강등 건수를 따로 찍는다. 후보에서 빠진 노드는 판정 기회 없이 무관으로 처리되므로 판정 F1과 섞어 보면 원인을 못 찾는다. 평가는 저장된 결과를 재사용하지 않고 매번 다시 판정한다. 자세한 사용법은 `eval/README.md`에 있다. 현재 골드셋 10쌍은 모델 예측을 시드로 넣은 것이라 검토 전 점수는 의미가 없다.

`scripts/`의 `verify_*.py`는 실제 Claude와 Voyage를 호출해 각 툴의 동작을 확인하는 스크립트다.

## 배포

GitHub Actions, GHCR, Argo CD, k3s 순서의 GitOps 배포다.

- `.github/workflows/ci.yml`: 모든 푸시와 PR에서 pytest와 웹 빌드(타입 검사 포함)를 돌린다. main에 푸시되면 api·web 이미지를 GHCR에 올리고, `deploy/k8s/kustomization.yaml`의 이미지 태그를 커밋 SHA로 바꿔 다시 커밋한다.
- `deploy/k8s/`: kustomize 매니페스트. api(파드 2개), web, Postgres(StatefulSet), Traefik Ingress(`/api`·`/mcp-server`는 api, 나머지는 web).
- `deploy/argocd/application.yaml`: Argo CD가 `deploy/k8s`를 보고 클러스터를 자동으로 맞춘다.

처음 한 번은 클러스터에서 직접 준비한다. 매니페스트와 Argo CD 설정의 `OWNER`를 GitHub 사용자명으로 바꾼 뒤:

```bash
kubectl create namespace research-copilot
kubectl -n research-copilot create secret generic copilot-secrets \
  --from-literal=ANTHROPIC_API_KEY=... --from-literal=VOYAGE_API_KEY=... \
  --from-literal=POSTGRES_PASSWORD=... \
  --from-literal=DATABASE_URL='postgresql+asyncpg://copilot:<비밀번호>@postgres:5432/copilot'
kubectl apply -n argocd -f deploy/argocd/application.yaml
```

GHCR 이미지를 private으로 두면 같은 네임스페이스에 `ghcr-pull`이라는 이름의 이미지 pull secret도 만든다. Secret은 Git에 넣지 않는다(`deploy/k8s/secret.example.yaml`은 형식 예시일 뿐이다).

## 운영 중 대비한 장애와 조치

각 항목은 로컬에서 재현해 확인했고 테스트로도 남겼다.

- MCP 세션 404: 상태 유지 모드에서는 세션이 파드 메모리에 있어, 다른 파드로 간 요청이 404가 된다(api 컨테이너 2개로 재현). MCP를 무상태 HTTP로 바꿨다(`MCP_STATELESS_HTTP=true`).
- 크래시 루프: liveness에 DB 확인이 들어 있으면 DB가 느려질 때 정상 파드까지 재시작된다. `/livez`는 프로세스만 보고, `/readyz`만 DB를 2초 제한으로 확인한다. DB를 일시정지했을 때 `/livez`는 200, `/readyz`는 2초 만에 503인 것을 확인했다. 시작할 때 DB가 늦으면 60초까지 기다리며 재시도한다.
- OOMKilled: 메모리 실측(api 유휴 134MiB, 혼합 부하 12,000건에서 최대 153MiB)으로 requests 192Mi, limits 512Mi를 정했다. limit 96MiB에서는 기동 직후 OOMKilled(exit 137)가 재현된다.
- LLM 비용 급증: SDK 자동 재시도를 끄고 오류 코드별로 다룬다. 429는 `retry-after`만큼 기다리되 30초를 넘으면 바로 실패하고, 529·5xx·연결 오류는 지수 백오프로 두 번까지 재시도한다. 그 밖의 4xx는 재시도하지 않는다. 일시 장애가 연속 5번이면 서킷브레이커가 60초 동안 호출을 막는다. 하루 토큰 예산(기본 200만)을 DB에 모아 세고, 넘으면 호출하지 않는다. 현황은 `GET /api/usage`.

## 입력·판정·결과 전달에서 대비한 장애와 조치

LLM 서비스를 실제로 운영할 때 자주 보고되는 장애 유형을 미리 모아 보고, 지금 코드에서 그대로 터질 것을 고쳤다. 재현 가능한 것은 테스트로 남겼다(`tests/test_analyze_pipeline.py` 등).

- 잘못된 project_id: UUID가 아닌 값이 DB까지 가서 500이 났다. 지금은 형식 오류와 없는 프로젝트를 404와 원인 코드로 돌려준다.
- 보이지 않는 문자: 복사한 텍스트의 NUL 문자가 LLM 비용을 다 쓴 뒤 저장 단계에서 실패했다. 저장·분석 전에 NUL, 제어문자, 짝 없는 서로게이트, 제로폭·방향 제어 문자를 지우고 NFC로 맞춘다.
- 길이 무제한: 자료 전문이 노드마다 들어가 비용과 지연이 노드 수만큼 곱해졌다. 6만 자를 넘으면 분석 전에 거절하고, 8천 자를 넘으면 노드마다 관련 청크와 그 앞뒤만 발췌해 보낸다. 근거 문장 검증은 언제나 전문과 대조한다. 작업 전체에 필요한 토큰을 먼저 어림해 예산이 모자라면 시작하지 않는다.
- URL만 붙여넣기: 서버는 URL 내용을 가져오지 않는다. URL만 들어오면 거절하고 화면에서도 미리 안내한다.
- 청킹: 마침표 없는 표·개조식은 청크 하나로 뭉쳤다. 긴 구간은 겹치는 창으로 자른다. 청크는 원문 위치를 들고 다닌다.
- 근거 문장 대조: 공백만 정규화해서, 따옴표 종류·띄어쓰기·전각 문자가 바뀐 인용을 버리고 판정을 조용히 약한 관련으로 낮췄다. NFKC와 따옴표·대시 통일, 띄어쓰기 무시 비교, 근사 일치(92%)를 차례로 시도하고, 찾으면 원문 구간을 그대로 보여 준다. 6글자 미만 인용은 근거로 치지 않는다. 낮춘 경우는 결과에 표시한다.
- 프롬프트 경계: 자료 안의 `</자료>`가 경계를 깨고 지시문을 프롬프트 밖으로 꺼낼 수 있었다. 자료 속 태그를 무력화하고, 자료 안의 지시를 따르지 말라는 규칙을 넣었다.
- 판정 일관성: 같은 자료를 다시 넣으면 판정이 바뀔 수 있었다. 사용하는 모델(claude-sonnet-5)은 temperature 같은 샘플링 값을 바꿀 수 없어서, 같은 자료는 저장된 결과를 돌려주는 방식으로 일관성을 보장한다. 결과에 모델과 판정 기준 버전을 남긴다. thinking은 명시적으로 끈다(생략하면 이 모델은 켜진다).
- 출력 잘림: stop_reason이 max_tokens면 검증 재시도로 넘기지 않고 바로 알린다.
- 동시 호출: 자료 1건이 노드 수만큼 병렬 호출해 사용자 몇 명만 겹쳐도 429가 났다. 파드당 동시 호출을 4개로 묶었다.
- 부분 실패: 노드 하나가 실패하면 전체가 실패하고 앞서 쓴 비용이 버려졌다. 성공한 노드는 저장하고 실패한 노드는 따로 표시한다. 같은 자료를 다시 넣으면 실패한 노드만 다시 판정한다.
- 중복 제출: 같은 자료(공백 차이 무시)를 다시 넣으면 새로 분석하지 않고 저장된 결과를 돌려준다. 동시에 두 번 들어오면 한쪽만 접수한다.
- 결과 유실: 웹은 분석을 접수만 하고 바로 돌아온 뒤 상태를 주기적으로 확인한다. 결과는 DB에 남아 새로고침해도 다시 보인다. 끊긴 작업(15분 넘게 처리 중)은 다시 돌릴 수 있다.
- 오류 안내: 응답에 원인 코드를 붙였다(공급사 혼잡, 요청 한도, 예산 소진과 재충전 시각, 키·결제 문제, 입력 문제). 실패해도 입력 내용은 지우지 않는다.
- 배포 중 끊김: 종료 신호를 받으면 진행 중인 분석을 최대 280초 기다린다(terminationGracePeriodSeconds 300).
- 후보 누락: 형제 노드 임베딩이 거의 같아 엉뚱한 노드가 뽑혔다. 노드 임베딩에 상위 가설과 하위 질문을 붙이고, 내용이 바뀐 노드는 다시 임베딩한다. 약어·숫자처럼 임베딩이 약한 단어가 겹치는 노드에는 후보 자리 두 개를 내준다.
- 임베딩: 요청당 개수·글자 상한으로 나눠 보내고, 429 대기 총합을 45초로 제한한다.
- MCP: 툴 설명에 원문 전체를 요약 없이 넣으라고 적었다. 오류는 `[code] 메시지`로 돌려준다.

## 현재 한계

- 쿠버네티스에 실제로 올려 보지는 않았다. 매니페스트는 코드와의 정합성(probe 경로, 설정 키, 서비스 연결, 실행 UID)을 스크립트로 확인했고, 같은 보안 설정(읽기 전용 루트 파일시스템, root 아님)으로 도커에서 이미지를 돌려 확인했다.
- 메모리 실측에 LLM을 부르는 경로는 들어 있지 않다. 측정 당시 Anthropic 키가 만료돼 있었다. 키를 바꾼 뒤 자료 판정을 포함해 다시 재 볼 것.
- 서킷브레이커 상태는 파드마다 따로 가진다(토큰 예산만 DB로 공유).
- 인증이 없다. 공개 주소로 열 때는 Ingress에서 접근을 제한해야 한다.
- Voyage 무료 등급은 분당 3회 요청 제한이 있어 자료를 연달아 넣으면 임베딩 단계가 대기한다.
- 근거 문장 대조는 문장이 원문에 있는지만 본다. 그 문장이 가설을 실제로 뒷받침하는지(오귀속)는 사람이 확인해야 한다. warrant는 검증하지 않는다.
